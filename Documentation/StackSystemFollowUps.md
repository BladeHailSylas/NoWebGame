# Stack 시스템 후속 해결 과제

## 사용자 플레이 테스트 확인 (2026-11-23)

사용자가 사용 안내에 기재된 기대 결과를 실제 관측했다고 보고하여 안내 범위의 수동 검증을 완료로 갱신합니다. 아래 미실시 표기는 당시 기록이며, 예외·경계 조건은 기존 자동 검사 근거와 구분합니다. 별도 DR 절삭 및 미합의 정책의 해결을 의미하지 않습니다.

## STACK-CC-01 — 중복 CC 적용 후 행동 제한 카운터 잔류

### S4 코드/자동 검증 상태 (2026-11-18)

S1의 Key당 CC 단일 기여 수정에 더해, S2 Buff 총량·소유 기여와 S3 Trigger 준비/전체 소비/payload 만료 정리를 적용했습니다. S4는 Player/Enemy 파괴 시 Stack 소유 예약·기여·payload·큐 및 열린 Variable 소비 작업을 정리합니다. disable은 파괴가 아니며 기존 큐·누적 보존 정책을 유지합니다.

실제 Projectile 반복 명중 → Chain → StackMechanism 경로에 CC, Buff 중첩, Trigger 후속 Chain을 함께 연결한 자동 검사가 통과했습니다. CC 종료 후 제한 0, Buff 기여 회수 및 Trigger 소비 후 후속 Buff 만료를 확인했습니다. **사용자는 이번 S4 수동 전투 검증을 아직 실시하지 않았다고 확인했습니다.** 따라서 코드·자동 재현 수정 완료와 사용자 전투 재검증 미완료를 구분합니다. 아래 S1 및 Cast 종료 시점의 내용은 당시 기록입니다.

### S1 진행 상태 (2026-11-18)

동일 StackKey의 반복 적용마다 카운터를 올리고 만료 시 한 번만 내리던 원인을 수정했습니다. Key의 활성 주기당 CCContribution을 한 개 소유하며, 갱신은 수량/예약만 변경하고 종료는 그 증표를 한 번 해제합니다. 실제 Projectile Collider → onHit Chain → Collector → StackMechanism → Enemy의 StackManager 경로에서 2회 적용 후 만료 시 공격 제한 0과 CanAttack=true를 자동 확인했습니다.

`StackTransitionChecks`는 종류별 256회 갱신, 서로 다른 Key·혼합 CC, 0/음수/상한, 예약 실패 보상, Pending 취소 알림 예외, 재진입 및 무환급을 검사합니다. `StackBaselineChecks`의 CC 항목도 결함 fingerprint에서 정상 해제 검사로 전환했습니다. 기존 Cast 수명 회귀도 함께 실행합니다.

이 상태는 확인된 원인의 코드 수정과 자동 재현 회귀 완료를 뜻합니다. 실제 게임 씬의 사용자 재검증과 S4 전체 통합은 아직 남아 있습니다. Buff 총량과 Trigger payload 수명은 각각 S2/S3 대상이며 해결된 것으로 표시하지 않습니다. 아래 내용은 Cast Refactoring 종료 당시의 발견 기록입니다.

- 상태: 미해결, 사용자 확인 결함. 향후 Stack 시스템 재정비에서 조사·수정합니다.
- 발견 경로: Phase 4 수동 전투 테스트. Enemy AI가 발사한 Projectile의 Chain StackMechanism으로 CC를 반복 적용했습니다.
- 관찰: CC가 중복 부여되면 ImmovableCount 또는 InnoxiousCount가 정상적으로 해제되지 않을 수 있습니다. 정확한 발생 조건과 원인은 아직 확정하지 않았습니다.
- 영향: 이동/공격 제한이 의도한 CC 수명 이후에도 남을 가능성이 있습니다. Cast Commit에서 정상적으로 차단한 공격을 취소 로직의 오류로 혼동하지 않도록 구분합니다.
- 범위 결정: 사용자 승인에 따라 Phase 4 종료를 막지 않는 별도 해결 과제로 이관합니다. Phase 5에서도 이 문제를 해결된 것으로 간주하지 않습니다.

### 조사 및 수정 범위

Projectile → Chain → StackMechanism → StackManager 적용/갱신/중첩/만료/제거 → ActBridge.ApplyCC/RemoveCC 경로를 추적합니다. 동일 StackKey 반복 갱신, 다른 적용자의 동일 CC, CC 종류 간 중첩, 수량 변경, 일괄 제거와 비활성화 경계를 각각 확인합니다. 조사 전 특정 함수나 자료구조를 원인으로 단정하지 않습니다.

### 완료 기준

1. 실제 반복 명중 경로를 재현하는 회귀 검사를 추가합니다. 적용과 해제 호출을 균형 있게 직접 호출하는 검사만으로 대체하지 않습니다.
2. 해당 CC가 전부 종료되면 대응 행동 제한이 해제되고, 다른 유효 CC가 남아 있으면 제한이 유지됨을 확인합니다.
3. 갱신·소모·만료·명시 제거에서 중복 해제나 누락이 없고, CC 종류별 이동/공격 제한 계약을 보존합니다.
4. Cast 취소의 비용 무환급 및 이미 실행된 효과의 수명 회귀를 통과합니다.

### 현재 검증의 한계

Phase 4의 256회 CC 중첩 검사는 int 카운터의 증감 및 기존 byte 순환 문제를 검사합니다. 실제 Stack의 중복 적용·해제 수명 전체를 보장하지 않습니다. 따라서 해당 자동 검사 통과와 이 결함은 양립합니다.
