# v0.2 최종 플레이 테스트 결과 점검표

상세 절차·사전 조건은 [최종 플레이 테스트 가이드](V02FinalPlaytestGuide.md)를 따릅니다. 이 파일에 결과를 입력한 뒤 파일 전체를 전달하거나, 작성한 내용을 채팅에 붙여 넣으시면 됩니다. 여러 날 진행해도 되며 미실시 항목을 남긴 중간 결과도 전달할 수 있습니다.

## 작성 방법

- 결과 칸의 `미실시`를 `PASS`, `FAIL`, `BLOCKED` 중 하나로 바꿉니다. 필요한 설정·관측 수단이 없으면 BLOCKED로 기록합니다.
- 관측 칸에는 실제 수치·횟수·대상·시간을 적습니다. 실패하면 아래 결함 기록의 ID(F01 등)를 연결합니다.
- 일부만 성공한 항목을 전체 PASS로 처리하지 않습니다. 재시험은 이전 실패를 지우지 않고 `FAIL → PASS / 재시험 일시·수정 사항`을 남깁니다.
- 자동 검사 통과는 수동 결과를 대신하지 않습니다. 예외 주입·실행 중 재진입처럼 가이드에서 자동 검사로 보완한 경계는 근거를 따로 기록합니다.

## 고정 Entity 구성

Relation Profile은 기본적으로 LegacyLayer를 사용합니다. 이름과 레이어는 별개이며 시험 중 이름을 바꾸지 않습니다. DummyAlly도 AI를 끈 EnemyEntity로 구성할 수 있습니다.

| 이름 | 구성 | 레이어 | Spec 경로 / 설정 확인 결과 |
|---|---|---|---|
| Player | 사용자 입력 PlayerEntity | You | |
| DummyAlly | AI 없음 | Ally | |
| CasterEnemy1 | AI 활성 EnemyEntity | Foe | |
| CasterEnemy2 | AI 활성 EnemyEntity | Foe | |
| DummyEnemy | AI 없음 EnemyEntity | Foe | |

- [ ] 이름 5개가 위와 일치하고 중복되지 않습니다.
- [ ] AI의 기본 공격은 TowardsEntity이며 유효한 사거리를 사용합니다.
- [ ] AI Target Relations와 기술의 효과 허용 설정을 각각 확인했습니다.
- [ ] 필요한 피해 수신 대상에 실제 이름이 AllowEnemyDamage인 Variable을 연결했습니다.
- [ ] 두 Caster의 동일 Key 계열 비교에는 같은 Stack 정의를 사용합니다.
- [ ] 임시 자기 피해 Trigger는 해당 시험에서만 켭니다.
- [ ] 변경할 ScriptableObject는 복제본으로 분리했습니다.
- [ ] DR 수정 후 import·컴파일이 완료됐고 새 컴파일/누락 참조 오류가 없습니다.

**배치 전환:** 정량 시험에서는 두 Caster의 AI를 끕니다. 두 Caster가 Player에게 같은 CC를 적용하는 시험에서는 DummyAlly를 비활성화하거나 탐색 범위 밖에 둡니다. DummyEnemy는 두 Caster와 같은 진영이므로 기본 Enemy 선택의 공격 대상이 아니며 Player의 관측 대상으로 사용합니다. 진영 판정 시험에서는 DummyAlly를 다시 활성화합니다.
